## Intake Email Inbox, Live Conflicts, And Relationship Graph Ideas

Gabe proposed three larger next product ideas:

1. Intake Email Inbox -> Matter Creation
   - A firm creates `intake@firm.cmiforge.com`.
   - Someone emails engagement letters, demand letters, PDFs, screenshots.
   - CMIForge OCRs everything, identifies likely client, matter name, parties, practice area, and creates a draft intake.
   - It presents a confirmation like "We found Acme Corporation, John Smith, and ABC Insurance. Create matter?"

2. Conflict Search Before Submission
   - Instead of "Submit Intake -> Run Conflict Search -> Review Results," CMIForge evaluates conflicts continuously as the user types.
   - The sidebar can show similar matters, prior searches, related entities, and possible parent companies.

3. Relationship Graph
   - Visual graph for parties, subsidiaries, CEOs, opposing counsel, and related matters.
   - Especially valuable for conflicts because lawyers like seeing relationships instead of digging through tables.

We started implementing pieces of these ideas, especially the live conflict preview.

## 2026-06-20 Private Networking Addendum

Gabe approved the low-cost private-networking hardening path as long as it stayed roughly under $70/month of new spend.

Implemented:

- Created shared VNet `cmiforge-vnet`.
- Created App Service integration subnet `appsvc-integration`.
- Created private endpoint subnet `private-endpoints`.
- Added private endpoints for SQL `gwmatterforge`, Blob storage `cmiforgeattachasgmt7`, and Key Vault `cmiforge-kv-gw`.
- Linked private DNS zones for SQL, Blob, and Key Vault.
- VNet-integrated the demo app and Customer 0 app.
- Disabled public network access for Azure SQL and Blob Storage.
- Left Key Vault public network access enabled until secrets are moved and an operator access path is confirmed.

Follow-up automation updates:

- `deployme.ps1` can now VNet-integrate apps during deployment.
- `deploy/customer/provision-customer.ps1` defaults future tenant apps into `cmiforge-vnet/appsvc-integration`.
- Tenant blob containers are created through Azure Resource Manager so storage public access can stay disabled.
- The provisioning script can assign tenant app identities Key Vault secret-read access.
- Local SQL data-plane provisioning now requires an explicit `-AllowTemporarySqlPublicAccess` maintenance switch when public SQL access is disabled.
